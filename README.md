# LLAO — Lossless Audio Optimizer

Оптимизация аудиофайлов **полным перебором** всех поддерживаемых lossless-форматов и их
параметров. Из всех кандидатов выбирается результат минимального суммарного размера при
**полном сохранении аудио и тегов без потерь**. Победитель валидируется и заменяет исходный
файл. Подробности архитектуры и конвейера — в `PLAN.md`, схема конфигов — в `formats/README.md`.

> Это описание **конечного желаемого состояния** проекта. Текущий статус реализации — в `PLAN.md`.

## Ключевые свойства

- **Расширяемость.** В проекте нет зашитых конверторов. Каждый формат описан внешним
  JSON-конфигом в `formats/`: имя, URL утилиты, параметры сжатия, возможности по тегам/аудио.
  Добавление формата = добавление одного файла конфига, без пересборки.
- **Никаких потерь.** Аудио переносится побайтово (декод → эталонный PCM → кодирование →
  проверка декода против эталона). Теги переносятся полностью: каждый формат тегов хранится
  как отдельная группа и либо встраивается в целевой формат, либо выносится в ZIP-sidecar.
- **Полный перебор.** Время не ограничено; покрываются все форматы и все варианты сжатия
  из конфигов. Для каждого файла перебор идёт в отдельном процессе (параллельно, `--jobs`).
- **Самодостаточность.** Консольные утилиты кодеков скачиваются автоматически по URL из
  конфигов (с проверкой контрольных сумм) и складываются в `bin/<id>/`.
- **Windows-native.** Единый исполняемый файл `llao.exe` на C++17. Все кодеки — Windows-версии
  (конфиги содержат только `windows`/`any` записи). На Linux проект запускается под `wine`.
- **Статистика накапливается внутри ПО.** При каждой работе пополняется локальная статистика
  (формат, вариант сжатия, степень сжатия, тип контента). Форматы перебираются в порядке
  ранжирования по средней экономии: наиболее вероятные победители конвертируются первыми.
  Таблицу ранжирования показывает `llao.exe stats`.
- **Lossy-входы по умолчанию пропускаются.** mp3/aac и пр. не имеют смысла пережимать
  в lossless (размер только растёт); обработка — только с флагом `--allow-lossy`.
- **Контроль устаревания конфигов.** При скачивании утилиты её CLI сверяется с ожиданиями из
  конфига (`--help`); при расхождении выдаётся предупреждение, что версия/параметры изменились.

## Платформа и сборка

- **Целевая ОС:** Windows 10+. Распространение — один `llao.exe`, без установки и внешних
  библиотек (используется только встроенный в Windows WinHTTP/zip и внешние кодеки).
- **Сборка:** кросс-компиляция MinGW-w64. Рабочий тулчейн — [llvm-mingw](https://github.com/mstorsjo/llvm-mingw)
  (`export PATH="$HOME/opt/llvm-mingw-<ver>-…/bin:$PATH"; make`); системный пакет
  `g++-mingw-w64-x86-64-posix` не требуется. Makefile: `-std=c++17 -static -lwinhttp`.
- **Запуск на Linux:** `wine llao.exe …` (утилиты кодеков тоже Windows-версии и выполняются
  под wine). wine 10+ имеет WoW64: 32-битные утилиты (takc.exe, установщик Monkey's Audio)
  работают без пакета `wine32`.
- **Зависимости** (только для сборки): `nlohmann/json` и `miniz` — лежат в `third_party/`.

## Форматы (из `formats/*.json`)

| id | Формат | Расширение | Утилита | Каналы | Биты | Примечание |
|---|---|---|---|---|---|---|
| `flac` | FLAC | `.flac` | `flac.exe` | 1–8 | 8/16/24 | уровни `-0..-8`, MD5 |
| `wavpack` | WavPack | `.wv` | `wavpack.exe` / `wvunpack.exe` | 1–256 | 4–32 | `-h/-hh` + `-x0..-x6`, MD5 |
| `monkeys_audio` | Monkey's Audio | `.ape` | `mac.exe` | до 8 | 8/16/24 | уровни `-c1000..-c5000`; инсталлятор 32-бит (WoW64), сайт дросселирует скачивание — при первом запуске качается один раз, дальше извлекается `MAC.exe`+`MACDll*.dll` из кэша без установки |
| `alac` | Apple Lossless | `.m4a` | `ffmpeg.exe` | 1–8 | 16/20/24/32 | без уровней |
| `tta` | True Audio | `.tta` | `ffmpeg.exe` | 1–2 | 8/16/24 | без уровней (ttaenc не используется) |
| `tak` | TAK | `.tak` | `takc.exe` | до 6 | 16/24 | `-p0..-p4` + E/M-уровни (`-p4m`), CRC+MD5 |
| `optimfrog` | OptimFROG | `.ofr` | `ofr.exe` | 1–2 | до 32 | пресеты `0..10`+`max`/`--acm`/`--optimize`, MD5; встроенные APEv2-теги |
| `la` | LA | `.la` | `la.exe` | 1–2 | только 16 | только ID3v1; `la.exe`+`la-core.dll` извлекаются из NSIS-установщика (kind=extract7z, без установки) |
| `mpeg4_als` | MPEG-4 ALS | `.m4a` | `ffmpeg.exe` | 1–8 | 16/24/32 | кодер удалён из новых ffmpeg — выключен |

> ffmpeg-форматы (alac/tta/mpeg4_als) используют одну общую сборку BtbN `ffmpeg.exe`
> в кэше `bin/ffmpeg/` (скачивается один раз, не по одной копии на формат).

## CLI

```
llao.exe check-formats                      # валидация схемы formats/*.json
llao.exe tools [fmt_id ...] [--no-download] # статус/скачивание утилит в bin/<id>/
llao.exe optimize <файл|папка> [--jobs=N]   # основной перебор (один файл или рекурсивно)
                 [--formats flac,wavpack]   # ограничение набора форматов
                 [--no-download] [--dry-run] # без скачивания / без замены файлов
                 [--allow-lossy]            # обрабатывать и lossy-входы (mp3, aac, …)
llao.exe restore <файл|папка> [--jobs=N]     # обратная оптимизация: в целевой формат
                 [--to=flac]                # (по умолчанию FLAC), теги возвращаются
                 [--variant=<id>] [--no-download] [--allow-lossy]
llao.exe help <fmt_id> -- <аргументы>       # запуск утилиты (--help и т.п.)
llao.exe stats                              # показать накопленную статистику
```

`--jobs=0` (значение по умолчанию) — число параллельных процессов = число доступных ядер.

### Язык интерфейса

Вывод и сообщения (включая исключения и отчёты) локализуются через каталоги
`lang/<код>.json`. Язык выбирается в порядке приоритета:

1. Флаг `--lang=ru|en` (можно в любом месте командной строки: `llao.exe optimize ... --lang=ru`);
2. переменная окружения `LLAO_LANG=ru|en`;
3. поле `"language"` в `llao.json` рядом с `llao.exe` (`"auto"` по умолчанию);
4. автоопределение (`LANG`, затем язык пользователя Windows).

Английский — базовый (при отсутствии перевода в каталоге показывается английская
строка). Пример `llao.json`:

```json
{ "language": "ru" }
```

Пример сессии:

```bat
llao.exe tools
llao.exe optimize "D:\Music" --jobs=8
llao.exe restore "D:\Music\Album - B.wv" --to=flac   # вернуть файл в FLAC
```

## Как это работает (кратко)

1. `check-formats`/старт: читаются и валидируются все `formats/*.json`.
2. `tools`: для каждого включённого формата находится утилита — кэш `bin/<id>/` (для
   ffmpeg-форматов общий `bin/ffmpeg/`) → PATH → скачивание по URL
   (SHA-256), распаковка архива / извлечение из NSIS-установщика через 7-Zip
   (`kind: extract7z`, без установки; скачанный инсталлятор кэшируется и не перекачивается),
   всё под текущую ОС.
3. Для каждого файла (в отдельном процессе):
   - ffprobe-проба → если нужно, декод в эталонный WAV; lossy-входы и файлы с видеопотоком
     пропускаются (кроме `--allow-lossy`);
   - извлечение канонического набора тегов (текст, картинки, лирика, cuesheet, ReplayGain, главы);
   - перебор подходящих по `caps` форматов (в порядке ранжирования по статистике) и вариантов
     сжатия;
   - для каждого кандидата: кодирование → встроенная проверка → декод → побайтовое
     сравнение PCM с эталоном → запись тегов (embedded, если формат покрывает всё, иначе
     ZIP-sidecar `tags.json` + `pictures/`) → валидация тегов;
   - стоимость кандидата = размер файла (+ sidecar, если есть);
   - победитель = минимальная стоимость;
4. Победитель заменяет исходник: файл переименовывается в расширение формата-победителя
   (`.<name>.llao-tmp.<ext>` + `rename`), рядом копируется `.tags.zip` при его наличии;
   откат при недоступности каталога.
5. Каждый кандидат дописывается в локальную статистику `stats.json` (размер, вариант,
   степень сжатия, параметры аудио) — она накапливается между запусками и определяет
   порядок перебора форматов в следующих прогонах.
6. Всё логируется (JSONL) и сводится в отчёт: таблица форматов, экономия, причины исключений.

## Теги: групповая модель

- Каждый встреченный формат тегов (ID3v2, RIFF LIST INFO, Vorbis-коммент, APEv2,
  ID3v1, MP4 ilst) извлекается как отдельная группа (`TagSet.groups`).
- При сжатии (`allow_merge=false`) одиночная группа конвертируется в нативный тип целевого
  формата; при нескольких группах каждая встраивается в свой тип, если цель его поддерживает,
  иначе — в ZIP-sidecar (`tags.zip` v2: `tags.json` с `groups[]` и `pictures/`).
  Конфликтующие группы не мержатся.
- При восстановлении (`restore`, `allow_merge=true`) согласованный набор сжимается в одну
  нативную группу; конфликтующие группы пишутся отдельно (часть embedded, часть sidecar).
  Старые sidecar v1 тоже читаются.
- Стоимость кандидата — размер файла (+ размер sidecar); данные не теряются никогда.
