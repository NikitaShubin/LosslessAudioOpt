# Changelog

Все заметные изменения LLAO, новые сверху. Этот файл — базовый текст; [CHANGELOG.md](CHANGELOG.md) — английский вариант того же содержания. Текст для страницы релиза берётся из `CHANGELOG.md` (см. `release.yml`), то есть пользователь видит именно ту секцию версии, что здесь.

В версиях 1.x был статусбар в терминале и отдельный процесс `llao-daemon`. **Оба удалены в 2.0** — движок работает без консоли, а интерфейс открывается в браузере. Поэтому секции 1.x описывают интерфейс, которого больше нет; описанное там поведение движка остаётся актуальным.

## 2.2.0 — 2026-09-30

### Точки задач в веб-интерфейсе
Точки в строке файла больше не «просто прогресс»:
- исключённые по `caps` варианты помечаются по одной точке на вариант (жёлтые) с указанием причины, а не одной строкой на формат: у формата может быть подходящий вариант при неподходящей битности, и по одному списку «форматов исключён» это не читалось;
- кружок победителя и его индекс задачи переживают рестарт демона (в `queue.json` сохраняется пара `fmt`/`variant`);
- новое состояние `skipped` — серая точка для задачи, снятой не своей ошибкой, а прерыванием из-за ошибки соседней задачи: виновник (красный `failed`) отличается от жертв.

### Контракт ошибок
- сбой варианта в строгом режиме больше не заканчивается безымянным `Aborted: N file(s) failed`: файл закрывается **до** аборта, и его имя с причиной идут в вывод, `--report` и `stats.json`. Многострочные причины из stderr кодеков сворачиваются в одну строку;
- файлы, не дошедшие до конца из-за аборта, учитываются отдельной строкой `Not processed`, а не рисуются пустыми строками;
- частично скопированные файлы доставки удаляются и в Windows-, и в POSIX-ветке.

### `--formats`
`optimize --formats=<id>` с неизвестным id раньше молча отсекал все форматы (`no suitable candidates`, код 0). Теперь это `ERROR: unknown format '<id>'` с кодом 1 — так же, как `variants` отвергает неизвестный `fmt_id`.

### `llao stats --report=<file>`
Новая выгрузка пишет рейтинг форматов текстовой таблицей **без локализации** — только id форматов, размеры и проценты, — чтобы её можно было отдать автору кодека как есть. На реальной библиотеке в 3.6 ГБ рейтинг выглядит так:

```
tak               86.78%      3432 кандидата
monkeys_audio     84.63%      1895 кандидатов
optimfrog         83.88%      6080
la                83.27%      1484
wavpack           78.20%      9408
alac              77.20%       388
tta               73.19%       443
flac              45.09%      7203
```

Путь к базе переопределяется переменной окружения `LLAO_STATS_FILE`.

### Локализация
- `llao serve --help` переведён на английскую базу с переводом в `lang/ru.json` (раньше печатался сырым `printf` с кириллицей, то есть и русскому, и английскому пользователю показывался русский);
- ключи `usage()` в `lang/ru.json` приведены в соответствие с текущим текстом: 26 строк получили перевод, 11 устаревших ключей вычищены. Русский пользователь больше не видит английские строки в справке.

### Документация
README теперь двуязычный: `README.md` — английский (основной, идёт в релиз), `README.ru.md` — русский; схема конфигов разделена так же (`formats/README.en.md` / `README.ru.md`). В `AGENTS.md` добавлено правило синхронного обновления пар файлов. Этот файл и его русский вариант заведены одновременно с ним, чтобы у текста релиза появился источник в репозитории.

### Падения кодеров
Работа, которую в разработке версионировали как 2.1.3, вошла в этот релиз:
- путь через ffmpeg-фолбэк теперь канонизирует эталонный WAV — это убирает access violation (0xC0000005) в OptimFROG на фолбэке;
- падение кодера прерывает работу над всем файлом. Раньше остальные варианты продолжали крутиться на том же битом эталонном WAV, хотя результат заведомо не мог измениться: в `stats.json` было 7287 таких записей на один битый вход.

### Прочее
- Monkey's Audio обновлён до **13.26**;
- сборка пересобирает объекты при изменении заголовков (`-MMD/-MP`) — раньше оставались stale-объекты со старой раскладкой классов, что проявлялось как segfault или потерянные строки в vtable;
- `WavReader` получил явный `close()` с защитой от двойного закрытия хендла;
- демон отдавал в `/api/state` константу `ignore_errors: true`, из-за чего интерфейс показывал tolerant-режим, хотя демон работал строго.

## 2.1.2 — 2026-09-24

- канонизация WAV после нативного декода. Декод `.ape` через `MAC.exe` давал эталонный WAV с неканоническим заголовком (чанк `fact`, либо `bext`/`minf`/`elm1` перед `fmt`): OptimFROG падал с 0xC0000005 и не создавал файл, LA сообщал `invalid .wav header`. `media::canonicalize_wav()` приводит заголовок к каноническим 44 байтам `fmt`(16 PCM)+`data`, PCM копируется побайтово. Фолбэк через ffmpeg не нормализуется (его формат подходит обоим кодекам).

## 2.1.1 — 2026-09-11

- favicon с градиентом в веб-интерфейсе, версия в заголовке UI, стабильный ассет `llao-latest-win64.zip`.

## 2.1.0 — 2026-09-10

- очередь больше не зависит от рабочей директории демона: строка хранит абсолютный `root` и относительный путь, поэтому рестарт из любого каталога узнаёт свои источники. Раньше рестарт из другого каталога мог сообщить `source file not found` про каждую строку;
- `replace_file()` вместо `std::rename` при записи результата и discovery-файла: на Windows переименование не перезаписывало цель и могло оставить висящие `.tmp` или вторые записи.

## 2.0.0 — 2026-09-08

### Терминальный интерфейс удалён
Статусбар и отдельный процесс `llao-daemon` убраны. Движок работает без консоли, а интерфейс — в браузере: подкоманда `serve` поднимает HTTP-демон с веб-UI. CLI (`optimize`, `restore`, `tools`, `variants`, `stats`) и сервер живут в **одном бинарнике** — `llao.exe` / `llao-linux`.

### Демон и веб-UI
- HTTP-API и встроенный веб-интерфейс (без сборки, vanilla ES6, вшит в исполняемый файл): вход по токену, таблица очереди с точками вариантов, счётчики, добавление по пути, отмена файла/всей очереди, перестановка, удаление, пауза/возобновление, рестарт, выключение с подтверждением;
- персистентная очередь в `queue.json` (v2) рядом с discovery-файлом, обновляется при каждом изменении и при shutdown: строки `ok` переживают рестарт, активные продолжаются, остановленные и ошибочные сохраняют причину;
- мгновенное завершение процессов при remove/shutdown, watchdog подготовки с бюджетом времени, tombstones вместо призрачных строк, атомарный restart и удаление по id (а не по позиции);
- crash-безопасность: незавершённые строки честно помечаются при следующем старте, а запись результата транзакционна через временный файл — обрыв между шагами никогда не показывает ложное «готово».

### Архитектура
- теги и описания форматов перенесены в `formats/*.json` — ни имён форматов, ни таблиц теговых ключей в C++; новый формат добавляется одним JSON;
- монолиты декомпозированы: `serve.cpp` на `serve_entry`/`serve_session`/`serve_queue`/`serve_persist`, `optimize.cpp` (3128 строк) на `optimize_util`/`optimize_codec`/`optimize_runner`, `tags.cpp` (1845 строк) на модули по форматам; см. `docs/architecture-audit.md`;
- движок отвязан от UI через `obs::Sink` и превращён в долгоживущую очередь с публичным API `Engine`.

### Инфраструктура
- CI нативно собирает единый бинарник на Linux и гоняет весь набор тестов, `bin/` кэшируется по `formats/*.json`;
- dev-контейнер (llvm-mingw + wine32/64 + ffmpeg + p7zip) и обёртка `llao` под wine с настоящим синглтоном;
- в `stats.json` появились метрики производительности кандидатов: `wall_ms`, `prep_wall_ms`, `decode_wall_ms`.

## 1.4.0 — 2026-08-17

- кодеры запускаются так, что не могут унаследовать наши открытые дескрипторы. Раньше они наследовали транзитный дескриптор, и параллельная замена файлов падала с `ERROR_SHARING_VIOLATION`; ограничение наследования через `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` отклонено как нестабильное на реальном Windows, поэтому файлы открываются не-наследуемыми с `FILE_SHARE_DELETE`;
- работа по Ctrl+C: первое нажатие — аккуратная остановка, второе — принудительный выход, кодеры умирают вместе с процессом (Job Object с `KILL_ON_JOB_CLOSE`);
- окно подготовки больше не следует за числом не запущенных файлов, отмена проверяется в воркерах, неудачная замена считается ошибкой файла.
