## 5. Статусбар v2: цветовая модель, пути, прокрутка, проценты

Утверждённый план доработок (v1.5.1):

### Палитра состояний (src/status.cpp)
- задача **в работе** — оранжевый 208;
- задача **выполнена** — синий 27;
- задача **ошибка** — красный 196; задача **ждёт** (prepped) — серый 236;
- файл **подготавливается** (prep) — тёмно-оранжевый 130 (вся строка);
- файл **не начат** — чёрный 0 (вся строка);
- файл **обработан успешно** — зелёный 28 (вся строка);
- skip / ошибка файла — серый 240 / красный 196.

В `Row` добавить `bool prepping` (ставится в `prep()`, снимается в `set_tasks()`)
и `double win_pct` (процент выигрыша готового файла).

### Режимы полосы: прогрессбар (по умолчанию) / мозаика + Tab
- `BarMode { Progress, Mosaic }`, `g_mode = Progress`.
- Прогрессбар: те же `W` колонок / `total` задач, но по состоянию, не позиции:
  `t < n_ok` → синий, далее оранжевый (в работе), далее красный, в конце серый.
- Мозаика: позиционная раскраска (с новой палитрой).
- `VK_TAB` — переключение.

### Состояния файла (приоритет в `col_bg` для `whole==None`)
`done` → зелёный → `prepping` → тёмно-оранжевый → `!has_tasks` → чёрный →
иначе полоса (режим). Цепочка: чёрный → тёмно-оранжевый (распаковка) →
серый (готов к работе) → полоса → зелёный (готово).

### Проценты: выигрыш для готовых файлов + правый край
- `status::end_file(idx, pct)` — вернуть параметр выигрыша (убрали в Этапе A);
  из `finalize_file` передавать `savings`.
- Процент всегда выровнен по правому краю: файл в работе — прогресс,
  файл готов — процент выигрыша в сжатии (как в старой версии).
- skip/error/не-начат — без процента.

### Пути в списке + горизонтальная прокрутка
- `collect_files` возвращает `{path, rel}`: `rel` — путь относительно заданной
  директории (`fs::relative`), для файла-аргумента — просто имя. Обновить вызовы
  optimize и restore.
- Лейбл строки (`begin_file`) = `rel` вместо `base`.
- Глобал `g_hscroll` (сброс в `init()`); `VK_LEFT`/`VK_RIGHT` сдвигают все имена
  на 1 колонку (не трогают автоследование).
- Отрисовка лейбла: счётчик `[i/N]` фиксирован, справа — выровненный процент,
  между ними лейбл: помещается → целиком; `hscroll==0` → `голова...`;
  `hscroll>0` → `...середина...` / `...хвост` (многоточие и в начале пути).

### Подсказка в футере
- Показывать только если `!g_follow && g_total > g_height-1`. Текст расширить:
  `↑↓/PgUp/PgDn — прокрутка, ←/→ — по строке, F — следить` (ключ в lang/ru.json).

### CPU-время в статистике (вместо wall-time)
- `proc::Result` += `uint64_t cpu_ms`; в `proc::run` после завершения —
  `GetProcessTimes(pi.hProcess)` → `(kernel+user)/10000`, накапливать в
  `thread_local` (доступ `proc::child_cpu_ms()`).
- В `run_variant`: снимок `child_cpu_ms() + GetThreadTimes(GetCurrentThread())`
  в начале/конце → `rec["cpu_ms"]` (успех и `record_error`) + logger-событие
  `candidate`. Таймер растёт только при реальном выполнении — объективно при
  любом планировщике. Wall-time не сохраняем.
