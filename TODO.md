### v2.0 (IPC-демон и веб-UI)

- **Headless-демон** `llao-daemon.exe` (Windows) / `llao-daemon-linux` (ELF):
  движок оптимизации без консольного статусбара, управление через HTTP-API и
  веб-UI. Реализация — `src/serve.cpp`, `src/http_api.cpp`, `src/rpc.cpp`,
  `src/daemon_sink.cpp`, `src/events.cpp`. Опции сессии (`--jobs`, `--verify`,
  `--dry-run`, `--no-stats`, `--debug`, `--report`) + серверные (`--bind`,
  `--port` (0 = свободный), `--token`, `--no-auth`, `--discovery`).
- **Single-instance**: именованный мьютекс `Local\llao-daemon-singleton` —
  вторая копия демона отвергается (нельзя делить tmp-каталог и очередь).
  tmp — общий (без pid-подпапки), чистится при старте демона.
- **Discovery-файл**: `port`/`token`/`pid`/`version` в
  `%LOCALAPPDATA%/llao/daemon.json` (Linux: `$XDG_DATA_HOME/llao/daemon.json`);
  переопределение `--discovery` или env `LLAO_DISCOVERY`. Токен (64 hex)
  генерируется, если не задан `--token` явно.
- **Авторизация**: `Authorization: Bearer <token>` для всех `/api/*` и
  `/rpc`; `--no-auth` — только локальная отладка.
- **HTTP API**:
  - `POST /rpc` — JSON-RPC: `ping`, `stat`, `add`, `cancel-file`, `remove`,
    `bulk-cancel`, `bulk-remove`, `clear-done`, `sort`, `restart`,
    `pause`/`cancel-all`, `resume`, `reorder`, `shutdown`, `formats`, `debug`;
  - `GET /api/state` — снимок: версия, опции сессии, счётчики, пауза, строки
    очереди (id/путь/статус/задачи/проценты);
  - `GET /api/events?since=N` — событийный лог с `last_seq`/`resync`
    (delta-обновления UI, выживание разрывов соединения);
  - `GET /api/formats` — включённые форматы; `GET /` и `/static/*` — веб-UI.
- **EventBuffer + StateMirror**: демон зеркалирует состояние очереди и
  рассылает события (log/task/state/end_file/stopped/resumed/removed/reordered);
  UI строит таблицу из зеркала, события — только дельты.
- **Веб-UI** (`web/*.html/js/css`, вшивается `tools/embed_assets.py`):
  - добавление путей (рекурсивно) через кнопку «+» и модальное окно
    (Вход / Выход / флаг восстановления); очередь с чекбоксами и массовыми
    операциями (стоп/запуск/в начало/вверх/вниз/в конец/удалить), drag & drop;
  - статус — цвет фона строки (столбец «Статус» убран), прогресс: доля
    выполненных задач (синий) в работе, экономия у готовых (зелёный); у restore
    честные проценты (убыток при росте файла — серым); путь результата —
    относительно целевой папки; автоскролл за активными файлами в обе стороны
    (кнопка включения — в центре строки заголовка);
  - пауза всех, перезапуск остановленных, очистка только успешно завершённых,
    сортировка по пути, тёмный скроллбар, сохранение токена и настроек;
    служебный счётчик `seq` из шапки убран (остался только в `/api/events`).
  - Dev-режим: демон отдаёт `web/` из каталога запуска — правки без сборки.
- **Перезапуск файла** (`restart`): остановка (cancel + kill процессов),
  ожидание завершения, добавление НОВОЙ строки на место старой (зеркало и
  движок переупорядочиваются отдельно — у движка есть «зомби»-строки),
  снятие паузы. Исключено «исчезновение файла из списка».
- **Отчёт**: `--report PATH` пишет итоговый отчёт при shutdown (файл или
  каталог, имя с временной меткой).
- **Running-статус файлов**: строка очереди переходит в `running` при запуске
  задач (отдельное событие `state`) — раньше оставалась в `prep` до конца.

### v2.0 — демон: прерываемость и отзывчивость (A/B/C2)

- **A — прерываемая финализация**: winner-валидация в `finalize_file` опрашивает
  `j.kill_requested` / `proc::cancelled()/aborted()` после проверки кандидата;
  при остановке строка получает статус `stopped`, tmp-файлы кандидата удаляются,
  доставка результата не выполняется (нет «полу-обработанных» файлов без
  явного признака).
- **B — cancel до финализирующей строки**: `FileJob::finalizing` + доработка
  `remove_file` — для done-строки в активной финализации `remove_file` ставит
  `kill_requested` вместо молчаливого возврата; stop/remove из UI/API доходит до
  строки прямо во время валидации/доставки.
- **C2 — `j.m` не держится на decode/copy**: валидация (декод кандидата в WAV +
  побайтовое сравнение) и физическая доставка (rename/copy в цель, replace на
  месте) выполняются ВНЕ мьютекса `j.m` через `unique_lock::unlock()/lock()`;
  лок удерживается только при чтении/записи общих полей и summary. Как следствие
  `GET /api/state`, reorder и cancel не блокируются на время длинной валидации.
- Регресс: юнит-тест таймингов (test-unit), daemon-тесты (`test_tags`/`test_errors`).

### v2.0 — веб-UI: правки после рефакторинга

- Фикс «0% при restore»: clamp `savings < 0 → 0` применялся и к режиму
  восстановления (файл растёт, а проценты обнулялись) — ограничен только

  относительно целевой папки (против ложных префиксов — проверка границы

### v2.0 — персистентность очереди и crash-безопасная доставка

- **`queue.json` рядом с discovery** (`persist.cpp`, формат `version: 2`,
  порядок строк = порядок очереди, id не хранятся): гарантированный дамп при
  каждом изменении очереди + финальный в `shutdown` ДО остановки движка;
  автозагрузка при старте. `ok` → отражение (проверка `out_path` и его sidecar),
  `queued` → снова в движок (справедливая перепроверка исходника + sidecar),
  `prep/running` (обрыв) → `stopped` «остановлено при перезапуске (обработка не
  завершена)», `stopped/error` → как есть с причиной. Полные пути строк движка
  берутся из карты id→path; дедлок-защита: persist использует только снимки.
- **Crash-безопасная замена файла**: `util::replace_file(original, tmp, final)`
  — кандидат копируется в `.<имя>.llao-tmp.<ext>` рядом, старый файл удаляется
  (включая случай переименования), `tmp` переименовывается на место; резервной
  копии нет, при обрыве `queue.json` честно показывает неоконченную работу, а
  не ложное «готово». `.llao-bak` удалён из доставки.
- **Транзакционный sidecar**: `deliver_sidecar` — теги встроены → лишний
  `<имя>.tags.zip` удаляется; нужен внешний → атомарная замена через
  `.llao-tmp.tags.zip` + `replace_file`. Оба пути доставки (in-place и целевая
  папка, optimize и restore) приведены к единому коду; путь sidecar-кандидата
  фиксируется до переноса файла.
- **VUI**: подписи модала «Исходный путь»/«Целевая папка», title «Пересжатие во
  FLAC»; при `--no-auth` кнопка «Выйти» скрывается (автологин без токена);
  у stopped/error-строк бейдж `⚠` с причиной (`last_error`) в тултипе.
- **`tests/test_daemon_persist.py`** (`make test-daemon-persist`): P1–P7 —
  формат/местоположение queue.json, грациозный и аварийный перезапуски,
  исчезнувший исходник, транзакционный sidecar (без потери тегов и без
  `.llao-tmp.*`), no_auth, дедуп строк при повторном старте.

### v2.0 — метрики, watchdog, кэш гейта и живой sidecar

- **Метрики производительности** (`stats.json` + события логгера): у каждого
  кандидата появились `wall_ms`, `prep_wall_ms`, `decode_wall_ms` (коммит
  3d803e6). Проверено реальным прогоном (tak/p4m, 0.25-сек wav: wall 6145 мс,
  prep 599 мс, decode 201 мс); события `ok`/`error` несут те же поля.
- **Watchdog prep** (коммит 3c8b58c): у `prep_file` появился бюджет времени
  (`prep_timeout` из суммы декодов + константа); при зависании дочерней
  утилиты (wine ffprobe/cli_check) prep перезапускается, строка не застревает
  и при `jobs=1` не блокирует очередь.
- **Кэш `cli_check` гейта кодеков** (коммит ea6c902): результат проверки
  утилиты кэшируется в `bin/<id>/.cli-check` (по содержимому конфига формата);
  старт сервера и повторные прогоны не дёргают кодеки через wine.
- **Live `has_sidecar`** (коммит ca2e5b6): флаг наличия sidecar для строк
  демона вычисляется по диску (как в persist) — работает и для замены на
  месте, где `out_path` не заполнен.
- **Фикс гонки case 8** (коммит 743049f): cancel-file → re-add в тестах
  демона переведён на pause-паттерн (как case 7), гонка снята.

  read-only symlink, при неудаче — hardlink, затем пробует оригинал, затем
  временную копию. Копия удаляется немедленно после декода (не в cleanup сессии).
  Реализация в `util.cpp` (`create_readonly_symlink`, `create_hardlink`) с
  `#ifdef _WIN32` (CreateSymbolicLinkW + SYMBOLIC_LINK_ALLOW_UNPRIVILEGED_CREATE)
  и POSIX (symlink + chmod 0444).
- **Очистка JSON-артефактов ffprobe**: `strip_ffprobe_json()` в `media.cpp`
  удаляет `{`, `}` и пустые строки из вывода ffprobe перед включением в
  `probe.error` — предотвращает утечку `{ \n\n }` в сообщения об ошибках.
- **Единый механизм `files` для кэша кодеков**: во все archive-загрузки
  (flac, wavpack, optimfrog, tak, alac, tta, mpeg4_als) добавлено поле

  Удалён 32-битный `MACDll.dll` из monkeys_audio.json.
- **Скрипт упаковки релиза парсит JSON**: `release.yml` вместо ручных
  исключений (ffplay.exe) парсит `files` из `formats/*.json` и копирует в

### v1.9.0

- **Двухуровневая система бюджета диска**: `DiskBudget` — централизованный
  аллокатор с реальным `disk_free_bytes()` при каждом `try_reserve()`. Файловый
  бюджет (3–4×wav) резервируется при `prep_file()`, задачевый (1–2×wav) — при
  `take_work_locked()` для 2-го+ воркера. Первый воркер работает в рамках
  файлового бюджета. При нехватке места файл помечается `deferred` и повторяется
  когда диск освободится (без abort).
- **Защита от burst-распаковки**: `prep_allowed_locked()` требует наличие хотя бы
  1 idle распакованного файла (с `released == 0`), иначе все распакованные должны
  полностью выпустить задачи — предотвращает одновременную распаковку всех файлов.
- **`--tmp=<path>`**: новый CLI-параметр для указания временной папки (может быть
  RAMFS). `disk_free_bytes()` проверяет реальный диск этой папки.
- **Нативная Linux-сборка**: `make TARGET=linux` → `llao` (ELF). Порт через
  `#ifdef _WIN32` в proc.cpp, status.cpp, util.cpp, download.cpp и др. Wine
  обёртка в `proc::run()` автоматически оборачивает `.exe` аргументы с wine.

### v1.8.0

- **Stall detection**: `proc::OutputMonitor` в poll-loop `proc::run()` — если
  output-файл не растёт и CPU процесса ≈ 0, процесс завершается принудительно
  через 120 сек (`stall_timeout_sec`). Это ловит infinite loop кодеков, которые
  «думают» без прогресса (раньше ждали только wall-clock timeout).

  (OptimizerFROG, Monkey's Audio) на больших файлах больше не обрываются
  преждевременно.
- **Корректная модель следа планировщика**: заменена двухуровневой системой
  бюджета диска (DiskBudget) — см. v1.9.0.
- **Цветовая палитра UI**: футер (#262626), скроллбар трек (238) / бегунок

## 7. Этап 2 (далее): демон — новые идеи

- **TUI-клиент `llao attach`**: консольный прогресс поверх HTTP-API демона —
  управление без браузера, «повторный запуск llao подключает UI к работающему
  сервису» из исходной mocp-модели. Старый псевдографический статусбар удалён,
  поэтому TUI-клиент писать заново.
- **`--upload`**: передача файлов на хост демона (веб-UI / CLI); сейчас `add`
  на несуществующий у демона путь отклоняет с подсказкой
  «use --upload in client».
- **Drag & drop в очередь из файлового менеджера**: браузер не отдаёт
  абсолютные пути перетаскиваемых объектов, поэтому «дайте путь» невозможно;
  гарантированный вариант — загрузка содержимого: JS рекурсивно обходит дерево
  (`webkitGetAsEntry`) и собирает ZIP (STORE), демон принимает его новым RPC
  `add-upload`, распаковывает в каталог приёма и добавляет пути в очередь.
  Текстовый путь (`dataTransfer.text/plain`) делается дёшево, но капризен
  (в ряде браузеров путь в DnD не отдаётся). Отложено.
- **Persist очереди**: **РЕАЛИЗОВАН** — см. «v2.0 — персистентность очереди и
  crash-безопасная доставка» (раздел 0).
- **Безопасность**: HTTPS (или отладочный прокси), срок действия/повторная
  генерация токена, ограничение размера очереди и скорости добавления.
- **Windows-сервис / автозапуск**: старт демона при входе в сессию,
  менеджер жизненного цикла (stop/start/restart), запуск из планировщика.
- **restart(): путь пересозданных строк** — **РЕАЛИЗОВАН**: `restart()` после
  `add_locked` выставляет полный путь новой строки из движка
  (`st_->set_path(new_id, f.path)` и `set_had_sidecar`), чтобы persist писал
  абсолютный `Row::path`, а не label (см. раздел 0).
- **Watchdog для prep**: **РЕАЛИЗОВАН** — бюджет времени на подготовку файла
  (`prep_timeout` в конфиге, коммит 3c8b58c): при превышении prep перезапускается;
  покрыто в тестах демона.
- **`has_sidecar` для in-place**: **РЕАЛИЗОВАН** — live-проверка по диску
  (`has_sidecar_file`), как в persist; работает и для замены на месте
