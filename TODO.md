- **Единый механизм `files` для кэша кодеков**: во все archive-загрузки
  (flac, wavpack, optimfrog, tak, alac, tta, mpeg4_als) добавлено поле

  исключений (ffplay.exe) парсит `files` из `formats/*.json` и копирует в

  (ofs.exe, ofr_sfx.exe, metaflac.exe, wvgain.exe, wvtag.exe) автоматически
  исключаются. Экономия: ~8 MB в релизе, ~610 MB в локальном `bin/`.

### v1.9.0

- **Двухуровневая система бюджета диска**: `DiskBudget` — централизованный
  аллокатор с реальным `disk_free_bytes()` при каждом `try_reserve()`. Файловый
  бюджет (3–4×wav) резервируется при `prep_file()`, задачевый (1–2×wav) — при
  `take_work_locked()` для 2-го+ воркера. Первый воркер работает в рамках
  файлового бюджета. При нехватке места файл помечается `deferred` и повторяется
  когда диск освободится (без abort).
- **Защита от burst-распаковки**: `prep_allowed_locked()` требует наличие хотя бы
  1 idle распакованного файла (с `released == 0`), иначе все распакованные должны
  полностью выпустить задачи — предотвращает одновременную распаковку всех файлов.
- **`--tmp=<path>`**: новый CLI-параметр для указания временной папки (может быть
  RAMFS). `disk_free_bytes()` проверяет реальный диск этой папки.
- **Нативная Linux-сборка**: `make TARGET=linux` → `llao` (ELF). Порт через
  `#ifdef _WIN32` в proc.cpp, status.cpp, util.cpp, download.cpp и др. Wine
  обёртка в `proc::run()` автоматически оборачивает `.exe` аргументы с wine.

### v1.8.0

- **Stall detection**: `proc::OutputMonitor` в poll-loop `proc::run()` — если
  output-файл не растёт и CPU процесса ≈ 0, процесс завершается принудительно
  через 120 сек (`stall_timeout_sec`). Это ловит infinite loop кодеков, которые
  «думают» без прогресса (раньше ждали только wall-clock timeout).
- **Пропорциональный hard timeout**: `max(encode_timeout, ref_size/50KBps)`,
  потолок 7200 сек — вместо фиксированных 1800 сек. Медленные кодеки
  (OptimizerFROG, Monkey's Audio) на больших файлах больше не обрываются
  преждевременно.
- **Корректная модель следа планировщика**: заменена двухуровневой системой
  бюджета диска (DiskBudget) — см. v1.9.0.
- **Цветовая палитра UI**: футер (#262626), скроллбар трек (238) / бегунок
  (245) — визуально отделены от контента и полос состояний. **Обновлено в
  v1.10.0**: футер/скроллбар → единый тёмный teal (23), бегунок → яркий cyan (87).

### v1.6.x+

- **Показ причин ошибок в интерактивном статусбаре**: `status::log`/`error` в
  интерактивном режиме больше не подавляются молча — строки буферизуются,
  последняя ошибка показывается в футере красным, а весь накопленный список
  печатается после `shutdown()` (когда альтернативный буфер восстановлен).
- **Abort при любой ошибке без `--ignore-errors`**: ошибка варианта или файла
  немедленно останавливает прогон (rc=1). С `--ignore-errors` файлы помечаются
  skip и прогон продолжается.
- **Планировщик: окно считается на файл** — заменён двухуровневой системой
  бюджета диска (DiskBudget) — см. v1.9.0.
- **24-бит PCM для ffmpeg-форматов**: декод кандидатов alac/tta (и native-фолбэк
  источников) явно задаёт глубину `pcm_s16le/s24le/s32le` по битности файла.
  Раньше ffmpeg писал WAV в `pcm_s16le` по умолчанию, и 24-бит источники давали
  «PCM не совпадает: разное количество аудиоданных».
- **Вертикальный скроллбар** в статусбаре: виден, когда список не помещается
  в окно; клик по нему мышью прыгает в позицию.
- **Горизонтальная прокрутка всех строк**: `fit_scroll` теперь сдвигает не
  только длинные пути, но и короткие (единый сдвиг по всем строкам).
- **Широкие символы (CJK)**: ширина строк считается в колонках терминала
  (`screen::disp_width`), обрезка по колонкам, `screen::Buffer` корректно
  отрисовывает/стирает double-width глифы.
- **Лирика в ID3v2 (USLT)**: `id3v2_parse` пропускает content-descriptor перед
  текстом лирики и срезает trailing NUL. Раньше текст читался с ведущим `\0`, и
  валидация tta давала ложное «лирика не сохранилась».
- **Регрессионный тест O9** (`tests/test_tags.py`): fixture `lyrics.flac` с
  многострочной лирикой и спецсимволами (кавычки, `\`, переносы) →
  `optimize --formats=tta` → проверка дословного переноса в ID3v2-USLT;
  Python-парсер `read_id3v2` тоже пропускает дескриптор.
- **Левое многоточие как маска**: при `hscroll>0` первые 3 колонки окна — `...`
  (поверх контента), контент с колонки `hscroll+3`, правое `...` пока хвост
  обрезается; сдвиг плавный, без «прыжка» при первом `→`.
- **Drag скроллбара**: нажатие на бегунок захватывает его с сохранением смещения
  (`g_sb_drag_off`), движение мыши с зажатой кнопкой ведёт бегунок; клик по
  треку прыгает на позицию.
- **Ограничение горизонтального сдвига**: `max_hscroll_locked()` — правый край
  самого длинного лейбла остаётся видимым; clamp в `handle_input_locked` и
  `render_pass_locked`.
- **Изоляция tmp по PID + ASCII-имена**: временные файлы живут в `tmp/<pid>/`
  (подпапка на процесс — параллельные прогоны не конфликтуют и не удаляют
  файлы друг друга), внутри только ASCII-имена. Причина: ANSI-кодеры (la.exe)
  не могли открыть пути с символами вне системной кодовой страницы — японские
  имена превращались в `??` («File ...ref.wav not found», 0xC0000005).
  Финальные имена файлов — по-прежнему юникод (широкие API).
- **Приоритеты для отзывчивого интерфейса**: render-поток — ABOVE_NORMAL,
  воркеры — BELOW_NORMAL, дочерние кодеки — BELOW_NORMAL_PRIORITY_CLASS —
  навигация клавишами/мышью не тормозит под нагрузкой на CPU.
- **Индикация Ctrl+C**: футер сразу показывает «аккуратная остановка…»
  (рендер опрашивает `proc::cancelled()`, отдельной правки обработчика
  сигнала не нужно); повторный Ctrl+C — принудительный выход.
- **Починка M4A/ALAC-тегов** (найдена по ошибке «валидация тегов: поле BPM не
  сохранилось» на другом ПК): три бага в `src/tags.cpp` —
  (1) `mp4_ilst_parse` искал дочерние боксы с `moov`, а надо `moov + 4`
  (контент после заголовка), (2) `wr32be` — это append, а не overwrite, поэтому
  размеры боксов в писателе не перезаписывались (добавлена `wr32be_at`),
  (3) кастомные теги `----` читались со смещением name-бокса +12, правильно +8.
  Бонус: в `plan_tags` пустые значения полей больше не попадают в план
  (пустой `DESCRIPTION` больше не даёт ложную ошибку валидации).
- **Немедленное прерывание при ошибке без `--ignore-errors`**: вместо ожидания
  завершения активных процессов (кодеры/декодеры в других воркерах) llao теперь
  принудительно их завершает (`proc::abort_all()`/`aborted()`, по образцу
  `cancel()`). Прерванные задачи не считаются ошибками и не финализируются,
  файлы-жертвы выпадают из отчёта (как при Ctrl+C). Отличие от Ctrl+C: код
  возврата 1, а не 130.
- **Статусбар v2 (раздел 5) реализован целиком**: палитра состояний (в работе —
  оранжевый, готово — зелёный, prep — тёмно-оранжевый и т.д.), режимы полосы
  Progress/Mosaic с переключением Tab, проценты выигрыша по правому краю для
  готовых файлов, пути относительно корня (`rel`) + горизонтальная прокрутка
  `←/→` с многоточиями, подсказка в футере (`F` — следовать), CPU-время вместо
  wall-time в статистике (`proc::Result.cpu_ms`).

  можно экспериментировать быстро.

## 6. Этап 2: IPC-демон (mocp-модель)

Утверждено: делать сразу полноценным демоном, не файловой очередью.
Пока не начато (ожидает пуша Этапа 1 и теста на Windows).

Цель — убрать конфликты двух параллельных `llao` и позволить добавлять
папки/файлы в работающую оптимизацию, как mocp: выходишь из интерфейса в
консоль — работа продолжается в фоне, повторный запуск подключает консольный
UI к работающему сервису.

Составные части:

- **Фоновый движок (сервер)** — процесс без UI: планировщик + воркеры + тэги.
  Детект «уже запущен ли сервер для этой рабочей папки» при старте.
- **IPC** — named pipe `\\.\pipe\llao-<hash рабочего каталога>` (или localhost
  TCP). Протокол: JSON-сообщения:
  - клиент → сервер: `add_paths`, `query_status`, `cancel`, `detach`;
  - сервер → клиент: снимки состояния (список файлов, полосы/сегменты, футер,
    логи) и результаты.
- **UI-клиент** — отдельный процесс с существующим статусбаром: подключается
  к серверу, отрисовывает состояние из снимков, навигация клавишами/мышью
  остаётся в клиенте (снимки делают её локальной).
- **Динамический статусбар**: `g_rows`/`g_total` расширяются при
  `add_paths` (сейчас список фиксирован на `status::init(total_files)`).
- **Отцепление от консоли**: движок стартует как фоновый процесс
  (`CREATE_NO_WINDOW`/двойной запуск), UI завершается, работа продолжается.
- **Повторный запуск** `llao <путь>` при живом сервере → вместо второго
  прогона: подключить UI к серверу (+ добавить переданные пути в очередь).

Риски/замечания:
- tmp-изоляция по PID уже есть (Этап 1) — сервер должен пережить выход клиента
  и наоборот, поэтому имя pipe и рабочий каталог — единый ключ сессии.
- Теги/эталонный WAV/кандидаты остаются в `tmp/<pid сервера>/`; очистка — на
  стороне сервера при завершении.
- `--ignore-errors`, abort, `--debug` (jsonl) должны работать в серверном
  процессе так же, как сейчас.
